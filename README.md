# 🎭 Playwright Native Test Agents — POC Framework

## Overview

This framework demonstrates Playwright's **Native Test Agents** (introduced in v1.56), a trio of built-in AI modules that automate the full test lifecycle:

| Agent | Role | Output |
|-------|------|--------|
| 🎭 Planner | Explores the live app via MCP, writes a structured test plan | `specs/*.md` |
| 🎭 Generator | Reads the plan, verifies locators live, writes spec files | `tests/**/*.spec.ts` |
| 🎭 Healer | Runs failing tests, identifies broken locators, patches and re-runs | Updated `*.spec.ts` |
| 🔌 API Test Planner | Reads a Swagger/OpenAPI spec via a local MCP server, understands endpoints + schemas, writes a structured API test plan | `specs/api/*.api-plan.json` |
| 🔌 API Test Generator | Reads JSON API test plans and generates Playwright `APIRequestContext` tests | `tests/api/*.api.spec.ts` |

The agents communicate with the browser through Playwright's **MCP (Model Context Protocol)** server, which exposes the accessibility tree rather than raw DOM — making all generated locators role-based and resilient by default.

## Setup

### 1. Clone and install

```bash
git clone <your-repo-url>
cd pw-agents-poc
npm install
```

### 2. Install Playwright browsers

```bash
npx playwright install --with-deps chromium
```

### 3. Set up environment variables

```bash
cp .env.example .env
# Edit .env with your store URL and credentials
```

### 4. Create the auth directory

```bash
mkdir -p playwright/.auth
echo '{"cookies":[],"origins":[]}' > playwright/.auth/user.json
```

### 5. Scaffold the native agents

```bash
# Pre-create the directory to avoid ENOENT on Windows/Mac
mkdir -p .github/chatmodes
npx playwright init-agents --loop=vscode
```

> **Note:** Re-run `npx playwright init-agents --loop=vscode` every time you update Playwright to pick up new agent capabilities.

### 6. Install the API Test Planner's MCP server dependencies

```bash
npm install --prefix mcp-servers/openapi-tools
```

This installs `@modelcontextprotocol/sdk` and `@apidevtools/swagger-parser`, used by the local
`mcp-servers/openapi-tools/index.js` stdio server that powers the `🔌 api-test-planner` agent.

## Configuration

### `playwright.config.ts`

```typescript
import dotenv from 'dotenv';
import path from 'path';
dotenv.config({ path: path.resolve(__dirname, '.env') });

import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  fullyParallel: false,     // Required: agents share one MCP browser session
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  workers: 1,               // Required: single worker keeps MCP session stable
  reporter: 'html',
  use: {
    baseURL: process.env.BASE_URL || 'https://your-store.myshopify.com',
    trace: 'on-first-retry',
    screenshot: 'only-on-failure',
    storageState: 'playwright/.auth/user.json',
  },
  projects: [
    {
      name: 'setup',
      testMatch: /seed\.spec\.ts/,
      use: { storageState: undefined },
    },
    {
      name: 'chromium',
      use: { ...devices['Desktop Chrome'] },
      dependencies: ['setup'],
    },
  ],
});
```

## Agent Workflow

Open VS Code Chat with `Ctrl+Shift+I`. Select the agent from the dropdown at the top of the chat panel.

### 🎭 Planner

The Planner explores your live application and produces a structured Markdown test plan.

**Switch to:** `🎭 planner` in the VS Code Chat agent dropdown

**Example prompt:**
```
@playwright/planner

Explore the Shopify storefront and generate a test plan for the
following flow: PLP → PDP → Add to Cart.

Context files:
- Seed: tests/seed.spec.ts
- PRD: specs/shopify-add-to-cart.prd.md

Steps to cover:
1. Land on /collections/all (PLP) and confirm products are visible
2. Click a product card to navigate to the PDP
3. On PDP, select a variant (size or color) if variant selectors exist
4. Click "Add to cart"
5. Verify the cart icon/counter in the header increments
6. Navigate to /cart and confirm the correct product and quantity appear

Save the plan to: specs/shopify-plp-pdp-cart.md
Use getByRole and getByLabel locators only — avoid CSS selectors.
```

**Output:** `specs/shopify-plp-pdp-cart.md`

---

### 🎭 Generator

The Generator reads the Markdown plan and produces executable TypeScript spec files, verifying every locator against the live app before writing.

**Switch to:** `🎭 generator` in the VS Code Chat agent dropdown

**Example prompt:**
```
@playwright/generator

Read specs/shopify-plp-pdp-cart.md and generate Playwright tests.

Rules:
- Import from @playwright/test directly
- One spec file per top-level scenario section
- Use getByRole, getByLabel, getByText locators — avoid CSS selectors
- Add at the top of each file:
    // spec: specs/shopify-plp-pdp-cart.md
    // seed: tests/seed.spec.ts
- Save files under tests/shopify/

Verify each locator against the live app before writing it.
```

**Output:** `tests/shopify/*.spec.ts`

---

### 🎭 Healer

The Healer runs failing tests, replays broken steps, inspects the current UI, patches locators, and re-runs until the test passes.

**Switch to:** `🎭 healer` in the VS Code Chat agent dropdown

**Example prompt:**
```
@playwright/healer

The test tests/shopify/plp-pdp-cart.spec.ts is failing with a locator error.

Run the test, replay the failing step, inspect the current UI,
patch the broken locator, then re-run until the test passes.
```

### 🔌 API Test Planner

Reads a Swagger/OpenAPI document (local file under `api-specs/` or a URL) via the local `openapi-tools` MCP server,
enumerates endpoints, resolves request/response schemas, and writes a structured API test plan.

**Switch to:** `🔌 api-test-planner` in the VS Code Chat agent dropdown

**Example prompt:**
```
@playwright/api-test-planner

Read api-specs/petstore.openapi.json, understand all endpoints and schemas,
and generate a comprehensive API test plan covering happy path, negative,
boundary, and auth scenarios. Save the plan to specs/api/.
```

**Output:** one JSON file per tag/resource under `specs/api/`, e.g. `specs/api/pets.api-plan.json`,
containing an array of `{ feature, endpoint, method, testCases[] }` objects. Each endpoint's `testCases`
covers Positive, Negative, Authentication, Authorization, Validation, Boundary, Error Handling, and
Schema Validation scenarios, e.g.:

```json
[
  {
    "feature": "Users",
    "endpoint": "/users/{id}",
    "method": "GET",
    "testCases": [
      { "name": "[Positive] Get user with valid ID", "expectedStatus": 200 },
      { "name": "[Negative] Get user with non-existent ID", "expectedStatus": 404 }
    ]
  }
]
```

---

### 🔌 API Test Generator

Reads JSON test plans from `specs/api/*.api-plan.json` and generates Playwright tests using the built-in
`APIRequestContext` (`request` fixture) — no browser involved.

**Switch to:** `🔌 api-test-generator` in the VS Code Chat agent dropdown

**Example prompt:**
```
@playwright/api-test-generator

Read specs/api/pet.api-plan.json and generate tests/api/pet.api.spec.ts
covering every test case in the plan.
```

**Output:** `tests/api/<resource>.api.spec.ts` — one `test.describe` per feature, nested `describe` per
endpoint, one `test()` per test case (category-driven request/auth/payload/assertions), with
`test.fixme()` placeholders for "Not applicable" categories.

**Run API tests:**
```bash
npx playwright test --project=api
npm run test:api
npm run test:api -- tests/api/pet.api.spec.ts
```

## Shopify Test Flow

This framework is pre-configured for a **Shopify storefront** PLP → PDP → Add to Cart flow.

| Page | URL | Key Elements |
|------|-----|-------------|
| PLP (Product Listing) | `/collections/all` | Product cards, titles, prices |
| PDP (Product Detail) | `/products/<handle>` | Images, variant selectors, Add to Cart button |
| Cart | `/cart` | Line items, quantities, subtotal, checkout |

**Shopify-specific notes:**
- Variant selectors are radio buttons or `<select>` dropdowns depending on the theme
- The Add to Cart button has the accessible name `"Add to cart"` in default Shopify themes
- Cart count appears in the header, typically as an aria-label containing `"Cart"`
- Some stores use a **cart drawer** (slides in) instead of navigating to `/cart` — the Planner will detect and document this automatically

## Self-Healing Demo

Use this to demonstrate the Healer agent in action.

### Step 1 — Break a locator deliberately

In any generated spec file, change one locator to something invalid:

```typescript
// BEFORE (correct)
await page.getByRole('button', { name: /add to cart/i }).click();

// AFTER (deliberately broken)
await page.getByRole('button', { name: /BROKEN_LOCATOR_XYZ/i }).click();
```

### Step 2 — Confirm it fails

```bash
npx playwright test tests/shopify/plp-pdp-cart.spec.ts
# Expected output: 1 failed
```

### Step 3 — Invoke the Healer

Switch to `🎭 healer` and prompt:

```
@playwright/healer

tests/shopify/plp-pdp-cart.spec.ts is failing on the Add to Cart step.
Run it, find the broken locator, patch it, and re-run until green.
```

### Step 4 — Observe the patch

The Healer will add a comment like:

```typescript
// HEALED by 🎭 healer — <date>
// Original: getByRole('button', { name: /BROKEN_LOCATOR_XYZ/i })
// Reason: No element matched; found button with accessible name "Add to cart"
await page.getByRole('button', { name: /add to cart/i }).click();
```

## Best Practices

**Seed file discipline**
Keep `tests/seed.spec.ts` under 80 lines. Agents inject it as context on every call — a bloated seed wastes tokens before the agent starts working.

**Atomic scenarios**
Structure `specs/*.md` with numbered, independent sections. Each scenario should set up and tear down its own state with no dependency on other scenarios.

**Narrow Generator prompts**
Generate one scenario section at a time rather than the entire plan at once. This keeps each call well within the LLM context window.

**Regenerate agents after upgrades**
```bash
npx playwright init-agents --loop=vscode
```
Always re-run this after updating `@playwright/test` to pick up new agent tools and instructions.

**Locator preference order**
```
getByRole > getByLabel > getByPlaceholder > getByText > getByTestId
```
Never use CSS selectors or XPath in agent-generated code.

**Never commit secrets**
`.env` and `playwright/.auth/` are both in `.gitignore`. Use `.env.example` as the committed reference.

## Troubleshooting

| Error | Cause | Fix |
|-------|-------|-----|
| `ENOENT: playwright/.auth/user.json` | Auth directory missing | `mkdir -p playwright/.auth && echo '{"cookies":[],"origins":[]}' > playwright/.auth/user.json` |
| `ENOENT: .github/chatmodes/` | Chatmodes directory missing | `mkdir -p .github/chatmodes && npx playwright init-agents --loop=vscode` |
| Agents do nothing in VS Code Chat | VS Code < 1.105 or no LLM connected | Update VS Code and ensure GitHub Copilot is signed in |
| Planner stops mid-exploration | Context window limit hit | Break the prompt into smaller, single-scenario requests |
| `storageState` read error on setup project | Global `storageState` applied to setup | Confirm `use: { storageState: undefined }` is set on the `setup` project in `playwright.config.ts` |
